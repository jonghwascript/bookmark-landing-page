# Proposal

## Why

README의 "Layout calculations and percentages" 절은 각 `calc()`가 무엇을 계산하는지는 설명하지만, 왜 그 계산이 필요한지(고정값 대신 계산을 쓴 이유)와 어떤 상황에서 깨지는지는 설명하지 않는다. 나중에 값을 바꾸거나 다른 사람이 읽을 때 계산의 전제를 모르면, 안전하게 고칠 수 있는 값과 함께 바꿔야 하는 값을 구분할 수 없다.

현재 코드를 측정해 보니 실제로 깨지는 경우가 있다(Chromium, 일반 15px 스크롤바, 375·768·1024·1440·1600px, 루트 글꼴 16·20px).

- 히어로 왼쪽 여백의 `80px`은 고정 px이고 헤더 여백은 rem이라, 브라우저 기본 글꼴을 20px로 키우면 1440px에서 로고(175px)와 히어로 제목(155px)이 20px 어긋난다.
- 이메일 래퍼의 `18.75rem`은 16px 루트에서만 300px이라, 20px 루트의 768px 화면에서는 442px 양식 안에 버튼과 한 줄로 들어가지 않고 두 줄이 된다.
- 기능 이미지의 하단 여백은 768~1023px에서 이미지가 536px로 제한되면 실제 높이의 16%(66.6px)가 아니라 85.5px가 된다(README에 이미 일부 설명됨).
- 기능 배경의 `100vw`는 일반 스크롤바 폭을 포함해 배경이 화면 왼쪽 밖으로 7.5px 더 나가지만, 왼쪽 넘침은 스크롤을 만들지 않아 무해하다(모든 폭에서 가로 넘침 0).

## What Changes

- "Layout calculations and percentages"의 각 하위 절(컨테이너·히어로 정렬, 모바일 메뉴 여백, 기능 이미지 비율·여백, 장식 배경, 밑줄·FAQ 화살표)에 **Why** 한두 문장과 **Breaks when** 한두 문장을 추가한다.
- "What I learned"의 `18.75rem` 단락에 루트 글꼴 크기에 따른 한계를 덧붙인다.
- 375px에서 히어로 다운로드 버튼이 한 줄에 들어가도록 한 여백 계산(313px 줄, 304.8px 버튼 합, 약 368px 미만에서 줄바꿈)을 짧은 하위 절로 추가한다.
- "Breaks when" 내용은 위 측정처럼 확인한 사실만 쓰고, 측정하지 않은 추측은 넣지 않는다. 코드는 바꾸지 않으며, 발견된 깨짐을 고치는 일은 이번 범위 밖이다.
