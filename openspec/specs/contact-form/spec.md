# contact-form Specification

## Purpose
페이지 하단 이메일 연락 양식이 잘못된 입력을 시각적으로, 그리고 보조 기술로 알리되 실제 오류가 있을 때만 오류를 안내하도록 검증과 오류 표시 동작을 정의한다.

## Requirements

### Requirement: 오류 전 설명 없음

이메일 입력란은 SHALL 검증 오류가 표시되지 않은 동안 오류 메시지를 접근 가능한 설명으로 노출하지 않는다.

#### Scenario: 페이지 로드 후 빈 필드 포커스

- **WHEN** 페이지를 연 뒤 아무것도 입력하지 않고 이메일 입력란에 포커스한다.
- **THEN** 화면 읽기는 입력란의 이름("Email address")만 안내하고 오류 메시지는 읽지 않는다.
- **THEN** 입력란은 잘못된 상태로 표시되지 않는다.

#### Scenario: 오류 해소 후 포커스

- **WHEN** 오류가 표시된 상태에서 유효한 이메일로 고쳐 오류 메시지가 사라진 뒤 입력란에 다시 포커스한다.
- **THEN** 오류 메시지는 설명으로 읽히지 않는다.

### Requirement: 검증 실패 시 오류 안내

양식은 SHALL 비어 있거나 형식이 잘못된 이메일로 제출될 때 오류 메시지를 표시하고, 입력란을 잘못된 상태로 표시하며, 오류 메시지를 입력란의 설명으로 연결한 뒤 입력란으로 포커스를 이동한다.

#### Scenario: 잘못된 값으로 제출

- **WHEN** 빈 값이나 잘못된 형식의 이메일로 Contact Us를 누른다.
- **THEN** "Whoops, make sure it’s an email" 메시지가 표시되고 입력란은 aria-invalid=true다.
- **THEN** 포커스가 입력란으로 이동하고 화면 읽기는 오류 메시지를 입력란의 설명으로 안내한다.

#### Scenario: 오류 상태에서 수정

- **WHEN** 오류가 표시된 상태에서 입력을 유효한 이메일로 고친다.
- **THEN** 오류 메시지가 숨겨지고 aria-invalid=false가 되며 입력란의 설명 연결이 해제된다.

#### Scenario: 유효한 값으로 제출

- **WHEN** 유효한 이메일로 Contact Us를 누른다.
- **THEN** 오류 메시지는 표시되지 않고 입력란은 설명으로 오류를 노출하지 않는다.

### Requirement: 오류 상태 시각 표시

이메일 입력란은 SHALL 검증 오류가 표시되는 동안 빨간색 테두리와 오류 아이콘을 보여 주고, 입력한 글자가 오류 아이콘과 겹치지 않게 하며, 오류가 해소되면 정상 모양으로 돌아간다.

#### Scenario: 잘못된 값으로 제출

- **WHEN** 빈 값이나 잘못된 형식의 이메일로 Contact Us를 누른다.
- **THEN** 입력란 테두리가 빨간색(red-400)으로 표시되고 오른쪽에 오류 아이콘이 보인다.
- **THEN** 입력란 아래에 빨간 띠 위의 오류 메시지가 표시된다.

#### Scenario: 긴 입력값

- **WHEN** 오류 상태에서 입력란 폭보다 긴 값을 입력한다.
- **THEN** 입력한 글자는 오류 아이콘 영역 전에서 잘리며 아이콘과 겹치지 않는다.

#### Scenario: 정상 상태

- **WHEN** 페이지를 처음 열거나 오류를 유효한 값으로 고친다.
- **THEN** 입력란 테두리는 보이지 않고 오류 아이콘과 빨간 띠도 없으며, 크기와 여백은 변경 전 정상 상태와 같다.
