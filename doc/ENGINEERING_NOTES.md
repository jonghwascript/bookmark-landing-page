# Engineering Notes

## 2026-10-25 — 헤더·히어로 정렬과 탭 이미지 영역

### Hover 시 테두리로 인한 크기 변화

`border-transparent`는 테두리 색상만 지정하며 두께를 확보하지 않는다.
기본 상태에 테두리 두께가 없다가 `hover:border`로 1px 테두리가 생기면 크기와 주변 배치가 달라질 수 있다.

```html
class="border border-transparent hover:border-red-400"
```

기본 상태에서 `border`로 공간을 확보하고 hover에서는 색상만 바꾼다.

### 1275px의 출처와 적용 범위

`src/style.css`의 `page-container`는 다음과 같다.

```css
width: min(100%, 1275px);
margin-inline: auto;
```

`doc/figma-spec-result.md`에는 데스크톱 히어로 프레임 크기가 1275×486px로 기록되어 있다.
이 값이 컨테이너 너비의 출처로 보이지만, 해당 문서는 섹션마다 프레임 폭과 시작 위치가 다르다고 명시한다.
1275px을 모든 섹션의 공통 콘텐츠 폭으로 간주하지 않는다.

### 전체 너비 히어로의 텍스트를 헤더에 정렬하기

헤더에는 `page-container`와 `md:px-20`이 있다. 기본 간격 기준 `px-20`은 80px이다.
1440px 화면에서 헤더 콘텐츠 시작점은 다음과 같다.

```text
(1440 - 1275) / 2 + 80 = 162.5px
```

히어로도 같은 컨테이너를 사용하면 텍스트 정렬은 쉽지만, 이미지 배경이 화면 오른쪽 끝까지 이어지지 않는다.
현재는 히어로를 전체 너비로 두고 왼쪽 padding만 헤더 콘텐츠 시작점에 맞춘다.

```html
lg:pl-[calc(max(0px,(100%_-_1275px)/2)_+_80px)]
```

히어로 section에는 `lg:page-container`와 `lg:px-20`을 함께 남겨 두지 않는다.
이 방식에서는 별도 오른쪽 padding 없이 이미지 래퍼가 오른쪽 끝까지 이어진다.

| 화면 너비 | 헤더·히어로 텍스트 시작점 |
| --- | --- |
| 1440px | 162.5px |
| 1600px | 242.5px |
| 1920px | 402.5px |

위 계산은 부모가 화면의 가용 너비를 채우고 기본 rem 크기가 16px인 조건이다.
화면이 커지면 텍스트 시작점도 헤더와 함께 오른쪽으로 이동한다.

### Tailwind 임의 값과 계산식 주의점

- 왼쪽 padding의 반응형 클래스는 `lg:pl-[...]`이다. `lg-p-l-[...]`은 유효한 유틸리티가 아니다.
- 차이를 반으로 나누려면 `(A - B) / 2`처럼 괄호로 계산 순서를 명시한다.
- padding의 백분율은 자신의 너비가 아니라 containing block의 너비를 기준으로 한다. 여기서 `100%`를 자신의 최대 너비인 1275px로 해석하면 안 된다.
- HTML 클래스의 실제 공백은 클래스를 분리한다. 임의 값 안에서 공백이 필요하면 `_`를 사용한다. 예: `lg:basis-[min(48%,_540px)]`.

### 파란 배경의 위치 기준

히어로 이미지 래퍼의 `relative`가 `before:absolute`의 위치 기준이다.
`before:right-0`은 화면이 아니라 이미지 래퍼의 오른쪽 끝에 붙는다.
따라서 래퍼 바깥에 컨테이너 여백이나 오른쪽 padding이 있으면 배경도 화면 끝에서 떨어진다.
배경의 너비만 늘리면 `right: 0`은 유지되므로 왼쪽 방향으로 넓어질 뿐, 오른쪽 빈 공간은 해결되지 않는다.

`before:w-[76%]`는 이미지 래퍼 너비의 76%라는 뜻이다.
문서에서 비율의 산출 근거는 확인되지 않았다. 초기 스타일링에서 도입된 값이며 시각적으로 조정한 값으로 추정한다.
현재 전체 너비 히어로 구조에서는 기존 `before:right-0 before:w-[76%]`를 사용한다.

### 히어로 텍스트의 최대 너비

텍스트 영역에는 다음 데스크톱 설정을 적용했다.

```html
lg:m-0 lg:max-w-[540px] lg:basis-[48%] lg:px-0
```

`max-w-[540px]`로 최대 너비를 제한하고, `page-container`의 자동 margin을 `lg:m-0`으로 해제해 남는 공간이 정렬을 바꾸지 않도록 한다.
이미지 래퍼에는 `lg:grow lg:basis-[52%]`를 적용해 텍스트가 최대 너비에 도달한 뒤 남는 공간을 채우게 했다.

### Feature 탭의 시각 영역 크기 통일

원본 이미지 크기는 각각 536×346, 478×416, 440×380이다.
`w-full h-auto`로 표시하면 이미지 비율에 따라 높이가 달라진다.
공통 영역은 원본들의 최대 너비와 최대 높이를 조합한 **536:416 비율**로 정했다. Figma에서 직접 가져온 공통 프레임 값은 아니다.

```css
.c-feature-panel__visual {
  @apply relative aspect-[536/416] self-start w-full;
  margin-bottom: calc(100% * 416 / 536 * 0.16);
}

.c-feature-panel__image {
  @apply absolute inset-0 h-full w-full object-contain;
}
```

영역의 높이는 공통 비율로 결정하고, 이미지는 비율을 유지하며 가운데에 배치한다.
`self-start`는 가로 flex 배치에서 다른 콘텐츠의 높이에 맞춰 시각 영역이 늘어나는 것을 막는다.
영역의 크기가 같아져도 그림 자체가 차지하는 너비·높이는 원본 비율에 따라 다를 수 있다.

패널별 `--feature-image-ratio` 인라인 설정은 제거하고 아래쪽 여백 계산도 공통 비율로 통일했다.
데스크톱에서는 기존 `lg:mb-0`으로 아래쪽 여백을 해제한다.
이 여백 식의 `100%`는 부모의 너비 기준이므로, 향후 모바일에서도 시각 영역을 별도 너비로 제한하면 다시 검토해야 한다.

### 검증 범위

Feature 시각 영역 변경 후 `npm run build`가 통과했다.
브라우저에서 각 화면 너비와 탭 전환을 직접 확인한 결과는 이번 기록에 포함하지 않는다.
