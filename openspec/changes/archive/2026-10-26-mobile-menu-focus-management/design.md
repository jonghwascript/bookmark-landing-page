# Design

## Context

`#mobile-menu`는 header의 형제인 aside이며 hidden 속성으로 열고 닫는다. `src/main.js`에는 이미 닫기 버튼 초기 포커스, 트리거 포커스 복귀, Escape와 링크 선택 닫기가 있다. 빠진 부분은 포커스 순환과 배경 격리다. Tailwind의 lg 구간에서 메뉴와 트리거 표시 상태가 바뀐다.

## Goals / Non-Goals

**Goals:** 기존 DOM과 스타일을 활용하고, 모든 종료 경로에서 동일한 상태 복원 절차를 사용한다.

**Non-Goals:** 데스크톱 내비게이션 재설계, 새 라이브러리 도입, 메뉴 애니메이션 추가.

## Decisions

- aside를 유지하면서 `role="dialog"`, `aria-modal="true"`, 접근 가능한 이름을 부여한다. 네이티브 dialog 전환도 가능하지만 기본 스타일과 top layer 도입에 따른 레이아웃 변경을 피한다. aria-modal 선언만으로 배경 차단을 대신하지 않는다.
- 메뉴 외부의 body 자식에 inert를 적용하고 각 요소의 이전 값을 저장한다. 닫을 때 원래 값을 복원한다. aria-hidden만 사용하는 방식은 키보드 접근을 막지 못하므로 선택하지 않는다.
- 열 때 닫기 버튼에 포커스를 이동한다. Tab 처리 시 현재 표시되고 활성화된 포커스 가능 요소를 조회하여 처음과 끝을 연결한다. 메뉴 밖으로 포커스가 이동하면 닫기 버튼으로 되돌리는 보호 처리를 둔다. 포커스 가능한 요소가 없으면 tabindex=-1인 메뉴 자체로 이동한다.
- 종료 처리를 하나로 모아 배경 복원, hidden 및 aria-expanded 동기화, 포커스 복귀를 수행한다. 닫힌 상태에서 중복 호출해도 상태를 바꾸지 않는다.
- lg 화면 폭 전환 시 메뉴를 닫고 배경을 복원한다. 트리거가 숨겨진 경우 헤더 홈 링크 같은 표시된 내비게이션 요소로 포커스를 이동한다. 모바일에서 닫을 때는 항상 트리거로 복귀한다.

## Risks / Trade-offs

- 기존 inert 상태 손실 → 변경 전 상태를 저장하고 정확하게 복원한다.
- 숨김 또는 비활성 요소로 포커스 이동 → Tab 순환 대상을 현재 렌더링 상태로 필터링한다.
- 데스크톱 전환 후 페이지가 계속 비활성화됨 → 실제 lg 구간과 일치하는 미디어 쿼리로 종료 처리를 실행한다.
- 보조 기술 동작 차이 → 키보드 브라우저 검증과 별도로 화면 읽기 탐색에서 배경 제외 및 복원을 확인한다.
